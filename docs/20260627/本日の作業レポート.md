### 1. EAS channel 欠落 + RevenueCat キー未設定の根本修正（Build 20）

前回（Day 12）のペイウォール価格空・購入失敗の根本原因を特定・修正。

**真因**:
- `eas.json` の全プロファイルに `channel` が未設定 → Build 19 は `channel: none` → **OTA を一度も受信できていなかった**
- `EXPO_PUBLIC_REVENUECAT_IOS_KEY` が `eas.json env` に未記載 → `eas build` は `.env.local` を読まないため、RevenueCat キーがバンドルに含まれていなかった
- EAS Update（OTA）は `eas.json env` を読まない（EASサーバー側の環境変数のみ） → `eas env:create` でサーバー側にも設定

**修正内容**（コミット `87ee947`）:
```json
// eas.json
{
  "build": {
    "production": {
      "channel": "production",  ← 追加
      "env": { "EXPO_PUBLIC_REVENUECAT_IOS_KEY": "appl_..." }  ← 追加
    },
    "qa": {
      "channel": "qa",
      "env": { "EXPO_PUBLIC_REVENUECAT_IOS_KEY": "appl_...", "EXPO_PUBLIC_QA_PREMIUM": "1" }
    }
  }
}
```

### 3. HealthKit ライブラリ移行（`react-native-health` → `@kingstinct/react-native-healthkit`）

**症状**: 「ヘルスケアを接続する」ボタンを押しても反応しない。診断パネルで `error: undefined is not a function` を確認。

**真因**: `react-native-health` v1.19.0 は**旧アーキテクチャ専用**。Expo SDK 55 はデフォルトで新アーキテクチャが有効になっており、`AppleHealthKit.initHealthKit` が `undefined` になっていた。`app.json` に `newArchEnabled: false` を追加しても `Podfile.properties.json` に伝播せず効果なし。

**解決策**: `@kingstinct/react-native-healthkit` v14（Nitro Modules ベース、新アーキテクチャネイティブ）へ移行（コミット `7920152`）。

| 変更ファイル | 変更内容 |
|------------|---------|
| `package.json` | `react-native-health` 削除、`@kingstinct/react-native-healthkit ^14.0.2` + `react-native-nitro-modules ^0.35.10` 追加 |
| `app.json` | プラグインを `@kingstinct/react-native-healthkit` に差し替え、`newArchEnabled: false` 撤回（Nitro は新アーキ必須） |
| `lib/health/permissions.ts` | `isHealthDataAvailable` / `requestAuthorization` に切り替え。`HealthPermissionResult {granted, error}` で診断情報を返す設計に |
| `lib/health/sync.ts` | `queryCategorySamples` / `queryQuantitySamples`（Promise ベース）に切り替え。コールバック API を完全排除 |

## 💡 学び・メモ

- **`eas build` は `.env.local` を読まない**。`EXPO_PUBLIC_*` をビルドに焼き込むには `eas.json` の `env` セクションに書く。EAS Update（OTA）はさらに別で EAS サーバー環境変数（`eas env:create`）が必要。
- **`channel` がないと OTA を永遠に受信できない**（`channel: none` 扱い）。`eas.json` の全プロファイルに明示的に書く。
- **新アーキテクチャ（New Architecture）移行の落とし穴**: `app.json` の `newArchEnabled: false` は `Podfile.properties.json` に自動伝播しない（再 prebuild が必要）。新アーキ対応ライブラリ（Nitro Modules）を使う方が根本解決。
- **HealthKit の read 権限は「許可/拒否」をアプリから判定できない**（iOS プライバシー設計）。「接続済み」フラグ（`HEALTH_CONNECTED_KEY`）を `app_settings` に永続化して管理する。
