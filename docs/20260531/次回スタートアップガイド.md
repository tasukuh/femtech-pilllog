## 🔔 通知システムの設計（Day 9 で刷新）

> **重要**: 通知周りを触る前に必ずこの設計を理解すること。

### 基本方針: 日付別 DATE 通知のローリングウィンドウ

- `repeats:true`（毎日繰り返す 1 個の通知）は **使わない**。
  → 「今日分だけ抑制」が原理的に不可能で、cancel するとシリーズ全体が消えるため。
- 代わりに **今日〜12 日先まで各日を個別の DATE 通知**としてスケジュールする。
- 各通知の `data` は `{ kind, dateStr }`。`dateStr`（"yyyy-MM-dd"）で「その日の分」を特定する。

### 各関数の役割（`lib/notifications/setup.ts`）

| 関数 | 役割 |
|------|------|
| `scheduleDailyReminders({ ..., skipToday })` | 古いピル通知を全消去 → 今日〜12日先のウィンドウを構築。過去時刻はスキップ。`skipToday=true` で今日分を除外 |
| `cancelFollowUpReminders()` | **今日分のみ**キャンセル（`dateStr`=今日）。未来日は残す。服薬・スヌーズ時に呼ぶ |
| `cancelAllPillNotifications()`（内部） | `data.kind` が `pill-*` の通知を全消去 |
| `scheduleOneShotReminder()` | スヌーズ用の単発 DATE 通知（`dateStr`=今日 付き） |

### 呼び出しタイミング

- **アプリ起動時**（`app/_layout.tsx`）: 毎回 `scheduleDailyReminders()` でウィンドウ再構築。
  当日が服薬済みなら `skipToday=true`。DATE 通知は毎日 1 日分ずつ消費されるため補充が必須。
- **設定変更時**（`app/(tabs)/settings.tsx`）: `scheduleDailyReminders()` で再構築。
- **服薬・スヌーズ時**（`markDoseAsTaken` / SNOOZE_30 ハンドラ）: `cancelFollowUpReminders()` で今日分のみ消去。

### foreground 抑制（`lib/notifications/handlers.ts`）

アプリ表示中は、当日服薬済みなら `pill-primary` / `pill-reminder` / `pill-evening` を抑制する。
（バックグラウンド/ロック中は cancel 側で対応）
