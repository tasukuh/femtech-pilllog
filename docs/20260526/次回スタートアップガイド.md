---

##### 2. EAS リモートの buildNumber を明示的に "10" にセット

これが **最重要ステップ**。前回はこれを飛ばしたので buildNumber=1 のままビルドされて衝突しました。

```bash
eas build:version:set --platform ios
```

対話プロンプトが出ます:

```
? iOS app build number (current: 1)?
```

→ **`10`** と入力して Enter

> なぜ "10" まで飛ばすか:
> - Apple 側にすでに Build 1 が登録済み（Day 5 配信）
> - Day 5 で「Build 2」を作った形跡もあり、未知の番号衝突を避ける
> - 大きく飛ばしてもアプリのバージョン表記（1.0.0）には一切影響なし

---

##### 3. 再ビルド

```bash
eas build --platform ios --profile production
```

- `autoIncrement: true` により、リモート値 "10" → ビルド時に **11** にインクリメント
- ビルド時間: 約5〜10分
- 完了するとメール通知が届く

##### 4. 完了後 submit

```bash
eas submit --platform ios --latest
```

ビルド番号が App Store Connect 側と衝突しないので、今回は通るはず。

##### 5. App Store Connect で確認

https://appstoreconnect.apple.com/apps/6772404120/testflight/ios

「テスト中」タブで **1.0.0 (11)** が表示されていれば成功。

## 🔧 トラブルシューティング

### submit が「buildNumber 衝突」で失敗する

**症状**:
```
Build number X for app version 1.0.0 has already been used.
```

**対処法**:
1. `eas build:version:set --platform ios` を実行
2. 現在値より大きい数字（+5 程度の余裕を持って）を入力
3. 再ビルド → 再 submit

---

### 通知が実機で来ない

**確認ポイント**:
1. **iOS 設定 → 通知 → ピルログ**: すべて ON か？
2. **集中モード**: ピルログが許可されているか？
3. **アプリ起動時のログ**: 「Daily reminders missing — rescheduling」が出ているか？
4. **Xcode コンソール**: `[Notifications]` ログを追跡

**最終手段**:
- アプリの「すべてのデータを削除」→ 再オンボーディング
- 通知許可ダイアログを再度承認
