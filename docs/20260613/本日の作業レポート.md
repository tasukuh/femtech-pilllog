## ✅ 完了したタスク

### A. RevenueCat 課金基盤

**`lib/premium.ts` の差し替え**:
- `usePremium()` を `{ isPremium, isLoading }` を返すフックに拡張。
  既存の `const { isPremium } = usePremium()` 分割代入はそのまま動く（後方互換）。
- RevenueCat `getCustomerInfo()` で entitlement `'premium'` の有無をチェック。
- `addCustomerInfoUpdateListener` で購入後リアルタイムに反映、アンマウント時に解除。
- iOS 以外 / RevenueCat 利用不可環境では `false` にフォールバック（クラッシュしない）。

**`app/_layout.tsx`**:
- 起動時の `initialize()` 内で `Purchases.configure({ apiKey })` を **一度だけ**呼ぶ。
  `usePremium()` 内では呼ばない（毎レンダリングを避けるため）。
- API キーは `EXPO_PUBLIC_REVENUECAT_IOS_KEY` 環境変数から読む（未設定時は warn のみ）。

**ペイウォールトリガーの結線（3 箇所）**:
| ファイル | 変更前 | 変更後 |
|---------|--------|--------|
| `app/(tabs)/history.tsx`（月移動） | `console.log('Show paywall')` | `router.push('/modal/paywall')` |
| `app/(tabs)/history.tsx`（古いメモ） | `console.log('Show paywall (note)')` | `router.push('/modal/paywall')` |
| `app/(tabs)/settings.tsx`（複数ピル） | `console.log('Show paywall')` | `router.push('/modal/paywall')` |

### B. ペイウォールモーダル（`app/modal/paywall.tsx` 新規）

- 既存の `app/modal/dose-log.tsx` と同じモーダルパターン（`presentation: 'modal'`）。
- `Purchases.getOfferings()` で価格を動的取得し、CTA ボタンに `〇〇円 で購入` と表示。
- 機能 3 点（全履歴閲覧 / 睡眠相関 / 心拍相関）をアイコン付きで訴求。
- 「購入を復元する」ボタン（`restorePurchases()`）。
- 「買い切り・追加料金なし」を明示。

### C. Apple HealthKit 連携モジュール（`lib/health/` 新規）

| ファイル | 役割 |
|---------|------|
| `lib/health/permissions.ts` | 権限要求（睡眠・安静時心拍の **read**）・利用可否確認。iOS 以外は noop |
| `lib/health/sync.ts` | HealthKit から睡眠・安静時心拍を取得し `health_samples` にキャッシュ |
| `lib/health/correlations.ts` | **純粋関数** `buildWeeklyCorrelations()` → 12 週分 `WeekBucket[]` |
| `lib/health/queries.ts` | TanStack Query 用。キャッシュ鮮度チェック → 再取得 → 相関計算 |

**設計上のポイント**:
- `correlations.ts` は副作用ゼロの純粋関数（DB も HealthKit も触らない）。単体テスト容易。
- 睡眠は iOS 16+ の sleep analysis 値（`asleepCore/Deep/REM` と legacy `asleep`）のみ集計し、
  `inBed`/`awakeInBed` を除外して日別の睡眠**分**を算出。
- HealthKit データは `health_samples` テーブルに**ローカルキャッシュ**（24h TTL）。
  サーバー送信は一切なし（CLAUDE.md の「健康データは完全ローカル」を遵守）。

### D. データ層（`health_samples` テーブル）

- `lib/db/schema.ts` に `healthSamples` テーブル + 型を追加。
- `lib/db/index.ts` に**マイグレーション 0003** を追加（schema v2 → v3）。`resetDB` 対象にも追加。
- `lib/db/queries/healthSamples.ts`（新規）: 期間取得・upsert・鮮度チェック・90日超の剪定。
- 既存ユーザー（schema v2）は**次回起動時に 0003 が自動適用**される。

### E. 可視化 UI

| ファイル | 役割 |
|---------|------|
| `components/domain/CorrelationChart.tsx` | `react-native-svg` で棒グラフ + 2 折れ線（追加ライブラリなし） |
| `components/domain/HealthDashboard.tsx` | Premium ゲート / 権限プロンプト / チャート表示を統括 |

- **チャート**: 服薬遵守率を棒グラフ（70%未満は赤）、睡眠を緑の折れ線、安静時心拍を橙の折れ線で
  オーバーレイ。X 軸は 3 週ごとに日付ラベル、凡例付き。
- **ゲートロジック**:
  - 未購入 → ロックアップカード（価値訴求 + ペイウォール誘導）
  - iOS 以外 → 非表示
  - 権限未取得 → 「ヘルスケアを接続する」プロンプト
  - 正常 → 12 週相関チャート
- **免責**: チャート下部に「このグラフは参考情報です。医療アドバイスではありません。」を明示
  （CLAUDE.md の医療文脈ルールに準拠）。

### F. 設定画面に「ヘルスケア連携」セクション追加（iOS のみ）

- Premium 済み: 権限管理行（拒否済みなら `Linking.openSettings()` で iOS 設定へ誘導）。
- 未購入: Premium バッジ付き行 → ペイウォールへ。

### G. 既存バグの巻き込み修正

`lib/db/queries/doseRecords.ts` の `clearFutureDoseRecords()` にあった型エラー
（`(doseRecords.scheduledDate as any) > today`）を Drizzle の `gt()` 演算子に修正。
これにより `tsc --noEmit` が**エラーゼロ**で通るようになった。
