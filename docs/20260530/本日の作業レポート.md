### Bug 1: カレンダー達成率のカウントずれ（タイムゾーンバグ）

#### 症状

- カレンダーに5つの ✓ マークが表示されている
- 月次達成率が「5/5回」ではなく「4/4回 = 100%」と表示される

#### 根本原因

`lib/db/queries/doseRecords.ts` の `calculateAdherenceRate` 関数内：

```typescript
// 修正前（バグあり）
const now = new Date();
const relevant = records.filter(
  r => new Date(r.scheduledDate) <= now && !r.isPlacebo
);
```

`new Date("2026-05-28")` は **UTC midnight**（= JST 09:00）に変換される。
JST 09:00 より前（例: 08:40）に確認すると `new Date("2026-05-28") > now` が **true** となり、
今日の記録が「未来の予定」として除外される。

一方 `CalendarGrid` は `setHours(0,0,0,0)` でローカル midnight を使うため、
同じ日付でも ✓ を正しく表示する → **画面と数値の不一致**が発生。

#### 修正内容

**`lib/db/queries/doseRecords.ts`**（`calculateAdherenceRate` 関数）:

```typescript
// 修正後
const todayStr = format(new Date(), 'yyyy-MM-dd');
const relevant = records.filter(
  r => r.scheduledDate <= todayStr && !r.isPlacebo
);
```

`scheduledDate` は "yyyy-MM-dd" 文字列で保存されているため、文字列の辞書順比較で
タイムゾーンに左右されない正確な判定が可能。

#### 修正前後の動作比較

| 状況 | 修正前 | 修正後 |
|------|--------|--------|
| 08:40 に確認（JST）| 今日分が除外 → 4/4 ❌ | 今日分を含む → 5/5 ✅ |
| 09:00 以降に確認 | 偶然正しく表示 | 常に正しく表示 ✅ |

### Bug 2: 服薬記録後も主通知（PILL_PRIMARY）が来る

#### 症状

- 朝に服薬してアプリで記録した
- 設定した通知時刻（例: 8:00）に主通知「おはようございます」が届く

#### 根本原因

前セッション（Day 7）で実装した `cancelFollowUpReminders()` が
PILL_REMINDER_1/2/EVENING しかキャンセルせず、**PILL_PRIMARY を残していた**。

```typescript
// Day 7 時点（不完全）
export async function cancelFollowUpReminders(): Promise<void> {
  await Notifications.cancelScheduledNotificationAsync(NOTIFICATION_IDS.PILL_REMINDER_1).catch(() => {});
  await Notifications.cancelScheduledNotificationAsync(NOTIFICATION_IDS.PILL_REMINDER_2).catch(() => {});
  await Notifications.cancelScheduledNotificationAsync(NOTIFICATION_IDS.PILL_EVENING).catch(() => {});
  // PILL_PRIMARY が残ったまま → 設定時刻に発火し続ける
}
```

#### 修正内容

**`lib/notifications/setup.ts`**（`cancelFollowUpReminders` 関数）:

```typescript
// 修正後: 全 ID をキャンセル
export async function cancelFollowUpReminders(): Promise<void> {
  for (const id of Object.values(NOTIFICATION_IDS)) {
    await Notifications.cancelScheduledNotificationAsync(id).catch(() => {});
  }
  console.log('[Notifications] All reminders cancelled after dose taken');
}
```

次回アプリ起動時に `areDailyRemindersScheduled()` が PILL_PRIMARY の不在を検出し、
`scheduleDailyReminders()` で翌日分を全て再スケジュールする既存の仕組みが機能する。

### Bug 3: スヌーズ後に通知がずっと来る

#### 症状

- 主通知から「30分後に再通知」を押した
- その後も +5分・+30分の通知が通常通り届き続けた

#### 根本原因

SNOOZE_30 ハンドラが one-shot スヌーズ通知を登録するだけで、
**CALENDAR repeats:true の繰り返し通知（PILL_REMINDER_1/2）をキャンセルしていなかった**。

```
主通知 (8:00) → ユーザーが SNOOZE_30 を押す
  → one-shot を 8:30 に登録
  → PILL_REMINDER_1 (8:05) は残ったまま → 5分後に発火 ❌
  → PILL_REMINDER_2 (8:30) は残ったまま → one-shot と同時に発火 ❌
  → ユーザーが 8:30 の通知でまた SNOOZE → 連鎖が続く
```

さらに、スヌーズ通知自体にも `categoryIdentifier: 'PILL_REMINDER'` が設定されているため、
「30分後に再通知」ボタンが付いており、エンドレスループが可能な状態だった。

#### 修正内容

**`lib/notifications/handlers.ts`**（SNOOZE_30 ブランチ）:

```typescript
// 修正前
} else if (actionIdentifier === 'SNOOZE_30') {
  const snoozeTime = new Date(Date.now() + 30 * 60 * 1000);
  await scheduleOneShotReminder(snoozeTime);
}

// 修正後
} else if (actionIdentifier === 'SNOOZE_30') {
  // 全 CALENDAR 通知をキャンセルしてから one-shot を登録
  await cancelFollowUpReminders();
  const snoozeTime = new Date(Date.now() + 30 * 60 * 1000);
  await scheduleOneShotReminder(snoozeTime);
}
```

合わせて import に `cancelFollowUpReminders` を追加。

#### 修正後のスヌーズ動作

```
SNOOZE_30 押下
  → cancelFollowUpReminders() → 全4通知キャンセル
  → scheduleOneShotReminder(+30分) → 1回限りの通知を登録
スヌーズ通知 (8:30) 発火
  → TAKE_NOW を押す → 服薬記録（通知は既にキャンセル済み）
  → または SNOOZE_30 → さらに+30分のone-shot（繰り返し通知なし）
次回アプリ起動
  → areDailyRemindersScheduled() = false → 翌日分を全て再スケジュール
```

## 🐛 既知の残課題

### 1. スヌーズ後にアプリを開かないと翌日以降の通知が失われる可能性

**状況**: スヌーズ後に全通知がキャンセルされる。アプリを1度も開かなければ
`areDailyRemindersScheduled()` が走らないため、翌日の通知が復元されない。

**実用的な影響**: 服薬するとアプリを開く（または TAKE_NOW を押す）ことが多いため、
実際には問題になりにくい。根本的な解決には Notification Service Extension が必要。
