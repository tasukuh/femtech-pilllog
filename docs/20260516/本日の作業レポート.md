## 🐛 遭遇した問題と解決方法

### 問題1: データベーステーブルが作成されない
**症状**:
```
ERROR: no such table: pill_medications
```
オンボーディング完了時にDBクエリが失敗

**原因**:
- アプリ起動時に `initDB()` を呼んでいたが、非同期処理の完了を待たずにUIが表示されていた
- マイグレーションが実行される前にクエリが走っていた

**解決策**:
1. `app/_layout.tsx` に `isDbReady` state を追加
2. `initDB()` の完了を待ってから UI をレンダリング
   ```typescript
   const [isDbReady, setIsDbReady] = useState(false);
   
   useEffect(() => {
     const initialize = async () => {
       await initDB(); // 完了を待つ
       setIsDbReady(true);
     };
     initialize();
   }, []);
   
   if (!loaded || !isDbReady) return null; // 待機
   ```

**学び**: React Native では非同期初期化処理の完了を明示的に待つ必要がある。ローディング画面の表示タイミングを制御することが重要。

---

### 問題2: SQLマイグレーションのパース失敗
**症状**:
```
ERROR: no such table: main.dose_records
```
マイグレーション実行中に特定のテーブルが作成されない

**原因**:
- 複数行にまたがる CREATE TABLE 文を単純に `;` で分割していた
- コメント行やCHECK制約内のカッコが誤解析の原因となっていた

**試した解決策**:
1. 最初の試み: 行ごとに処理してセミコロンまで蓄積
   - 改善したが、複雑なSQL文で問題が残った
   
2. **最終解決策**: SQL文字列のパースを廃止
   - 個別のSQL文を配列として明示的に定義
   ```typescript
   const MIGRATION_0001_STATEMENTS = [
     `CREATE TABLE IF NOT EXISTS pill_medications (...)`,
     `CREATE TABLE IF NOT EXISTS sheets (...)`,
     `CREATE TABLE IF NOT EXISTS dose_records (...)`,
     // ... 全10個のステートメント
   ];
   ```
   - 各ステートメントを順番に `execSync()` で実行
   - 詳細なログ出力（実行前/後）

**学び**: 複雑なパース処理は避け、可能な限り明示的な定義を使う。デバッグログは早めに充実させる。

---

### 問題3: ネイティブモジュール 'Burnt' が見つからない
**症状**:
```
ERROR: Cannot find native module 'Burnt'
```
開発中にトースト表示でクラッシュ

**原因**:
- `burnt` はネイティブモジュールで、シミュレータで動作させるには再ビルドが必要
- 一部のコードで `burnt` を直接インポートしていた

**解決策**:
1. `lib/toast.ts` ラッパーを作成し、`burnt` を一時的に無効化
   ```typescript
   // import * as Burnt from 'burnt'; // 一時的に無効化
   import { Alert } from 'react-native';
   
   export const toast = {
     success: (title, message) => console.log('[Toast] Success:', title),
     error: (error, fallback) => Alert.alert(fallback, message),
   };
   ```
   
2. ホーム画面など直接インポートしていた箇所を修正
   ```typescript
   - import { toast } from 'burnt';
   + import { toast } from '@/lib/toast';
   ```

**学び**: ネイティブモジュールは開発中に問題になりやすい。ラッパーを作って依存を隠蔽することで、後で簡単に入れ替えられる。

### 問題4: 通知トリガーの型エラー
**症状**:
```
Type '"date"' is not assignable to type 'SchedulableTriggerInputTypes'
```

**原因**:
- 文字列 `'date'` を使っていたが、expo-notifications は enum を要求

**解決策**:
Context7 で expo-notifications のドキュメントを確認し、正しい型を使用
```typescript
- trigger: { type: 'date' as const, date: scheduledDateTime }
+ trigger: { 
+   type: Notifications.SchedulableTriggerInputTypes.DATE,
+   date: scheduledDateTime 
+ }
```

**学び**: 公式ドキュメント（Context7）を早めに確認する。文字列定数より enum の方が型安全。

---

### 問題5: TypeScriptコンパイルエラー（複数箇所）
**症状**:
- `notification-permission.tsx`: `createMedication` に `id` プロパティがない
- `history.tsx`, `settings.tsx`: `ErrorDisplay` の `description` プロパティが存在しない
- `_layout.tsx`: `unsubscribe.remove()` メソッドが存在しない

**解決策**:
1. `createMedication` に明示的な `id` を追加
   ```typescript
   const medicationId = `med_${Date.now()}_${Math.random().toString(36).substring(2, 9)}`;
   await createMedication({ id: medicationId, ... });
   ```

2. `ErrorDisplay` の `description` を `message` に統合
   
3. `unsubscribe` の呼び出しを修正
   ```typescript
   - if (unsubscribe) unsubscribe.remove();
   + if (unsubscribe) unsubscribe();
   ```

**学び**: TypeScript strict モードは厳しいが、実行時エラーを防ぐ。エージェント実装後は必ず型チェックを実行する。

## 🎓 学んだこと・注意点

1. **React Native の非同期初期化**
   - 必ず完了を待つ state を用意する
   - ローディング画面の制御が重要

2. **Expo Notifications の制限**
   - シミュレータでは通知カテゴリが動作しない
   - Development Build が必要

3. **SQLite の特性**
   - FOREIGN KEY 制約はデフォルトで無効
   - マイグレーションは慎重に設計

4. **デザイントークンの価値**
   - 最初に定義すると一貫性が保たれる
   - コンポーネント実装が高速化

5. **エージェント活用**
   - 独立したタスクは並列実行で効率化
   - ただし依存関係があるものは順次実行
