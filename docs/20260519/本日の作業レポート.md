#### 3. ホーム画面の進捗計算が更新されない問題を修正

**問題**:
- 履歴画面で過去の記録を追加・削除しても、ホーム画面の進捗リングが更新されない
- 進捗計算が TanStack Query で管理されていなかった

**解決策**:
1. `getDoseRecordsBySheet` を `useQuery` でラップ
   - クエリキー: `['doseRecords', 'all', sheet?.id]`
2. 進捗計算の `useEffect` の依存配列に `allRecords` を追加
3. ミューテーション成功時に該当クエリを無効化
   - → 自動的に再フェッチされ、進捗が更新される

**変更ファイル**:
- `app/(tabs)/index.tsx`: 進捗データをクエリ化

#### 4. 未来の日付への誤記録を防止

**問題**:
- 未来の日付のモーダルで「服薬済みにする」ボタンが表示される
- 誤って未来の日付を記録してしまった場合、修正できない

**解決策**:

**Part 1: 未来の日付の制御**
- モーダルのボタン表示前に日付チェックを追加

  - 記録済み → 「記録を取り消す」ボタンを表示（誤記録の修正を許可）

**Part 2: 誤記録したデータのクリーンアップ**
- `clearFutureDoseRecords()` クエリ関数を追加
- 設定画面に「未来のデータをクリア」ボタンを追加
- 未来の日付で「taken」状態のレコードを「scheduled」に一括リセット

**変更ファイル**:
- `app/(tabs)/history.tsx`: 日付チェック追加
- `lib/db/queries/doseRecords.ts`: `clearFutureDoseRecords()` 追加
- `app/(tabs)/settings.tsx`: クリーンアップボタン追加

#### 5. TanStack Query のキャッシュ無効化を改善

**問題**:
- `invalidateQueries` は呼ばれているが、UIが即座に更新されない
- クエリキーが画面ごとに異なり、一部のクエリが無効化されていなかった

**解決策**:
1. `refetchType: 'active'` を追加
   - アクティブなクエリのみを即座に再フェッチ
2. 履歴画面で使用している全クエリキーを無効化
   - `['doseRecords']`
   - `['currentSheet']`
   - `['monthStats']`
3. `await` で無効化完了を待つ

**変更ファイル**:
- `lib/queries/hooks.ts`: `useMarkDoseTaken()` と `useUndoDoseRecord()`

## 🎓 学んだこと・注意点

### 1. AsyncStorage のハイドレーション問題
- Zustand の `persist` はハイドレーション完了を待つ仕組みが必要
- シンプルなデータならデータベースに保存する方が確実

### 2. TanStack Query のキャッシュ管理
- `invalidateQueries` だけでは不十分
- `refetchType: 'active'` で即座に再フェッチ
- クエリキーの一貫性が重要

### 3. 日付処理の注意点
- `startOfDay()` で時刻をリセットしてから比較
- データベースには `yyyy-MM-dd` 形式の文字列で保存

### 4. 段階的実装の効果
- Phase 1（データベース層） → Phase 2（Query層） → Phase 3（UI層）
- 各層を独立してテストできる
- 問題の切り分けが容易
