#### 2. 通知システムの修正と実装

**問題1: 通知がスケジュールされない**

**原因**:
- オンボーディング完了時に `setupGradualReminders()` が呼ばれていなかった
- 通知許可は得られていたが、実際の通知がスケジュールされていなかった

**修正内容**:
```typescript
// app/(onboarding)/notification-permission.tsx
- import { requestNotificationPermission } from '@/lib/notifications/setup';
+ import { requestNotificationPermission, setupGradualReminders } from '@/lib/notifications/setup';

// シート初期化後に通知をスケジュール
const todayRecord = await getTodaysDoseRecord(sheet.id);
if (todayRecord && todayRecord.status !== 'taken') {
  const [hours, minutes] = scheduledTime.split(':').map(Number);
  const scheduledDateTime = new Date();
  scheduledDateTime.setHours(hours, minutes, 0, 0);
  await setupGradualReminders(todayRecord.id, scheduledDateTime);
}
```

**結果**: ✅ 通知が正常にスケジュールされるようになった

---

**問題2: 通知設定がオンボーディングと連携していない**

**原因**:
- オンボーディングで設定した時刻が `medication` テーブルにのみ保存
- `notification_settings` テーブルが更新されていなかった
- 設定画面はデフォルトの 08:00 のまま

**修正内容**:
```typescript
// オンボーディング完了時に notification_settings も更新
import { updatePrimaryTime } from '@/lib/db/queries/notificationSettings';

await updatePrimaryTime(scheduledTime);
```

**結果**: ✅ オンボーディングで設定した時刻が設定画面に反映されるようになった

---

**問題3: 段階的リマインダーの間隔が仕様と異なる**

**元の実装**: `[0, 30, 60]` 分（4回目が遅すぎる）  
**仕様書**: 5分、30分、60分  
**ユーザーフィードバック**: 60分後は遅すぎる、UX的に良くない

**修正内容**:
```typescript
// lib/notifications/setup.ts
- const intervals = [0, 30, 60]; // minutes
+ const intervals = [0, 5, 30]; // minutes
```

**デフォルト値も更新**:
- `lib/db/schema.ts`: `[5,30,60]` → `[5,30]`
- `lib/db/index.ts`: マイグレーションのデフォルト値も同様に更新

**結果**: ✅ 3回の通知（設定時刻、5分後、30分後）に最適化

---

**問題4: ボタンテキストが固い**

**元のテキスト**: 「✓ 服薬済み」  
**ユーザーフィードバック**: 「今飲む」の方が自然

**修正内容**:
```typescript
// lib/notifications/categories.ts
- buttonTitle: '✓ 服薬済み',
+ buttonTitle: '今飲む',
```

**結果**: ✅ より自然な言葉づかいに

---

**問題5: 通知から記録してもホーム画面が更新されない**

**原因**:
- 通知ハンドラーで直接 DB を更新していた
- TanStack Query のキャッシュが無効化されていなかった
- 履歴画面は再取得するが、ホーム画面は古いキャッシュを表示

**修正内容**:

1. **共有 queryClient の作成**:
```typescript
// lib/queries/client.ts (新規作成)
export const queryClient = new QueryClient({...});
```

2. **通知ハンドラーでキャッシュ無効化**:
```typescript
// lib/notifications/handlers.ts
import { queryClient } from '@/lib/queries/client';

if (actionIdentifier === 'TAKE_NOW') {
  await markDoseAsTaken(doseRecordId, new Date(), 'notification');
  
  // キャッシュを無効化
  await queryClient.invalidateQueries({ queryKey: ['dose'] });
  await queryClient.invalidateQueries({ queryKey: ['doseRecords'] });
  await queryClient.invalidateQueries({ queryKey: ['sheet'] });
}
```

**結果**: ✅ 通知から記録した時、ホーム画面と履歴画面の両方が自動更新されるようになった

## 🔧 技術的な学び

### 1. EAS Development Build

- **Simulator Build vs Device Build**: Device Build は Apple Developer Program が必要
- **デバイス登録方法**: Website方式が最もシンプル（URLを開くだけ）
- **ビルド時間**: 初回は約20分、2回目以降は15分程度
- **デベロッパーモード**: iOS 16以降では必須、再起動後に確認ダイアログ

### 2. 通知システムのアーキテクチャ

- **通知スケジューリング**: オンボーディング完了時とアプリ起動時の両方で必要
- **段階的リマインダー**: UX を考慮して間隔を調整（60分後は遅すぎる）
- **キャッシュ無効化**: 通知ハンドラーから TanStack Query のキャッシュにアクセスする必要がある
- **共有 queryClient**: React外からもアクセスできるように singleton パターン

### 3. 開発効率

- **並行作業**: 法的ドキュメント作成は実機テスト中に実施できる
- **ユーザーフィードバック**: 実機テスト中にUX改善点が見つかる（ボタンテキスト、通知間隔など）
- **ドキュメント整備**: GitHub Pages で法的ドキュメントを公開すると管理が楽
